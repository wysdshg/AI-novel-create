# 骨架角色槽位补全（F8·转 to_plan）

> 状态: to_plan（2026-10-01 转，冷静期） | 建立: 2026-09-30 | 更新: 2026-10-01 | 上次验证: —（2026-09-20 八问核查实测确认）

## 为什么做（问题是什么）

75 条 active 骨架的 **361 个 cast 槽位全缺 ranks/traits**（旧 164 条有 506/498）。

## 争议点/后果链

- archetype_text() 少「位阶：」「性格：」两段 → char_archetype 867 块语义无性格
- → plans.py 建卡「功能位参考」返回空
- → PlanView.fillFromArchetype() 的 personality / background 自动起草**双双失效**
- 根因：label_skeleton_casts.py 的 prompt 与 validate() 压根没要求这两个字段

## 2026-10-01 新动态：拟升级全新模板机制（方向未定，冷静期）

用户指出病根更深：现 cast 是在**「概括后再概括」的骨架文本**上提取的
（原文 → 逐章摘要 → 弧归并 → 跨书凝练 → 提角色），天然提不出立体角色。
新方向：**从小说原文直接提取**，但消耗巨大。此前与 AI 的讨论未落盘（已散失），
待用户口述补记方向细节，三天冷静期后再评估。

## 候选方案（二选一，等新机制方向定了再拍）

- **新机制**：从原文提取角色（立体但消耗大）——若立项，下方小修作废
- **备查小修**：改 prompt + validate 加必填校验 → 重跑 75 条（约 75 次 LLM 调用）→ 回填三路向量——治标不治本（概括文本上提得更全一点，但提不出原文细节），**勿先花这笔钱**
