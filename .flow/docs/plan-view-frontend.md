# 篇规划前端页（P4）

> 状态: completed | 建立: 2026-09-30 | 更新: 2026-09-30 | 上次验证: 2026-09-30（vite build 复验通过 7.07s + pytest 全量单测 542/542；真机交互待用户确认——UI 类最终验收要用户过目）

## 为什么做

服务层的计划/选角/引入单/连续性能力都在，但没有页面就等于不存在（零入口病第五例教训）。

## 解决什么

一个页面看完整篇计划：表格编辑、选角、新角色引入、连续性警告，拍板后直接批量生成。

## 怎么实现

- 小说/篇双选择器 + 生成弹窗（口述 hint/章数/跳过模板）
- 计划表格行内编辑（beat/summary/钩子/召回/新角色/字数；超 3 新角色有剔除提示）+ 行级「AI 改这行」+ 拍板锁定
- 选角面板：槽位卡片（分数进度条 + 0.58 阈值线 + 手改/清空 + unmatched 高亮 + 重算）
- 引入单面板：按状态过滤、绑定槽位、确认建卡（可带角色属性）、忽略/恢复
- 连续性区：carryover 交接警告横幅 + 回归理由材料包折叠面板（三级 priority 标注）
- 侧栏「篇规划」入口同批上线

## 怎么扩展

- 后端 plan JSON 新增材料时记得 get_plan 要吐出、save_lines 要保留（有单测锁）
