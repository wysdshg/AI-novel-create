## 1 这个功能要演示什么

指定一条骨架（`plot_templates` id），对它的**每一环（beat）**把不同书的不同走法去重后并排摆出，
产出可直接注入写作上下文的「组装块」样张。**纯确定性，零生成式 LLM 调用。**

§8.1 定死的两条实测前提（别违背）：
- 真实弧 ≠ 完整骨架，多为「单环展开多段」→ **不要演示"填满 7 环"**，会大面积撞 0 路；
- **「某一环给 N 路走法」才是目标形态**；现在只有 1~4 路是灌书时间问题，**不补标**。

### 2.3 内嵌侧四处形态坑（组装逻辑必须处理）

1. **beat 标签两种格式**：merge 侧 `"A03 群殴混战×2"`（340 个），shaosong_singles 侧**裸原子号** `"G05"`（324 个）。
   严格式 `^([A-Z]\d{2})\s+名` 会漏掉 **49% 的环**——我自己第一版盘点就栽这里，结论一度写成「两料源零重合/各不相同」，实为误判（坑见 §4）。
2. **2 个 beat 标签是空格串 `" "`**（`秘境夺宝·拍卖竞价…`、`跨书骨架组#52`）→ 无原子号，只能显式标注不能猜。
3. **绍宋单弧侧 tags 全乱码**（324 处被拆成单字符列表，JSON 串被当可迭代二次展开）→ 组装不依赖 tags；merge 侧 1989 处正常。
4. **环引用非 active 原子**：`G09` **不在 `atomic_events`**（1 beat/1 走法）；`B08 非公平交易`、`C14 当众册封` 是 `status='candidate'`（4 条 / 2 条走法）。
5. 一致性核账干净：表侧 `atomic_id` 越表 0；`(book,segment_no)` 在 `chapter_summaries` 命中 335/335（segment_no 确为章号，符合 §5.0 输入层）；`book_name` 与 `arc_ref` 前缀 335/335 一致。语料 4 本书不在 `projects` 是设计如此（projects 只有 3 本在写作品），不是孤儿行。

## 3 去重口径：为什么必须用 embedding（实测）

- **字面指标全线失效**：同原子真实走法两两比对，字符二元组余弦/Jaccard/SequenceMatcher **没有任何一对 ≥0.5**（中位 0.05~0.19）。
  阈值扫 0.7/0.8/0.85/0.9/0.95，剩余路数**完全相同（489）**→ 字面口径下「sim≥0.85 合并」退化成「只并全等重复」，阈值形同虚设。
- 内嵌侧的重复恰好是机械重复：同一条 desc 最多出现在 **46 处**，2313 → 479 唯一。
- **bge-m3 才让 0.85 有意义**（网关 `127.0.0.1:9377`，`app/services/embedding_client.py`，dim 1024 已 L2 归一）：
  - 人工标定：同一事件两种写法 `cos=0.872`（该并）；不同事件 `cos=0.628`（该留）。
  - 真实语料：同原子两两中位 0.63~0.66，最高非全等 0.840/0.854 → 0.85 落在分布尾部，只切真近似重复，不误并不同走法。
  - A03/C01 各 435 对里，≥0.85 只有 1 对（C01 0.854，相邻章同一场诗会冲突的两个侧面 → 合并正确）。
- **定下的方案：两段式**——① 归一化（去空白）全等合并（零成本，兼治绍宋双计）② bge-m3 现算余弦 ≥0.85 合并，向量缓存 `outputs/f4_poc/vec_cache.json`（首跑 ≈489 条/31 请求，重跑零调用）。
- **零 LLM 验收怎么守**：任务单第 3 条显式允许「embedding 现算余弦走网关 bge-m3」；embedding 非生成式、不改写文本，样张每段文字都是库内原文。单测**注入假 sim 函数**，不依赖网关，pytest 离线可跑。

### 10.2 组装逻辑的关键决定

- **环定位**：`parse_beat` 用 `^([A-H]\d{2})\b`，兼容「A03 群殴混战×2」「G05」「（空）」三种标签（严格式会丢 49% 的环，见坑 F4-2）。
- **每环池**：该环内嵌 ∪ 表侧同原子全部 → 归一化全等合并 → bge-m3 单链接聚类（≥0.85）→ 簇代表取最长 → 跨书优先排序（同分保持首现序）。
- **脱敏**：长词优先替换；替换后再查一遍，**仍残留或正文 <40 字则整路剔除**（`render_route`）。占位词按词类人工指定在 `PLACEHOLDER_BY_WORD`，未列到的默认「某处」。
- **语义合并的可见性**：合并束常被每环展示上限折叠掉（4 张里只有 1 束进了正文），所以样张末尾加「**附 · 语义合并明细**」节，不受上限约束，逐束列出被并掉的成员原文＋出处＋余弦值，供人工核对「去重键有没有切错」。
- **零 LLM 的边界**：embedding 只做比较不改写文本，向量落 `vec_cache.json`；二次运行 4 张样张合计 0 次网关调用（全部缓存命中）。
