# 篇规划生成链路（P1）

> 状态: completed | 建立: 2026-09-30 | 更新: 2026-09-30 | 上次验证: 2026-09-30（pytest 全量单测复验 542/542，含 test_plan_crud.py / test_plan_s2.py；09-12 服务层真机：6 章退婚流计划 + 防幻觉剔除 3 个幻觉角色）

## 为什么做

一章一章想剧情效率低，且 AI 写整篇容易重复套路。先把整篇的章节计划排出来，人确认了再写。

## 解决什么

按作者口述 + 模板骨架，生成整篇的章级计划（每章节拍/钩子/召回角色/新角色/字数），并保证写章时任务卡注入不丢。

## 怎么实现

- plan_crud 生成/改行/拍板三段式；防幻觉剔除：计划里出现库中不存在的角色直接剔除
- _plan_prompt 瘦身：模板只送骨架名+节拍名，剥掉 variants 明细（2523→1167 字符，-53.7%）
- 拍板后 layer_chapter_plan 按 chapter_no 注入任务卡，P_CRITICAL 永不裁剪
- save_lines/refine_line 重写 plan JSON 时保留 carryover/reentry 材料（此前会洗掉，已修）

## 怎么扩展

- 模板检索的 q_list 来源是口述——无口述时 0 命中（F9 待拍板兜底）
- 「排除最近用过 + 跨书组轮换」检索策略未实现（03 §8.3）
