## 0. 使用规则（🔴 必须遵守）

1. **做完一项 → 同步更新 `docs/03`**（该阶段进度）+ `docs/02`（状态，含验证方式与日期）+ `CHANGELOG` 加一行。**不许只改本表**。
2. **本表清零后 → 归档或删除**（并入 `docs/_archive/`），不要让第二份清单长期存活 —— 两份清单必然漂移，这正是本表要解决的问题。
3. **每项的「验证」列是硬要求**：标 ✅ 必须有实测证据（pytest 输出 / Playwright 截图 / curl 返回 / DB 查询）。
   **读代码不算验证**（本项目铁律：不许凭读代码下结论，见 `docs/06 §2.1`）。
4. **不许把「计划」写成「修复」**：未做的事写「❌ 未做」，半做的必须写明**剩余哪一部分**。
5. **已清的项：压缩留痕，证据外移**（2026-09-15 新增，防两处漂移）——
   同一条证据**不能同时**写在本表和 `02/03`。做法：本表只留「一行结论 + 验证方式」，
   **证据明细写进 `02`**（或对应文档）并在本表标注指向；整类清完后压缩成一张小表，不再逐项维护。
