## 1. 这是什么

一个**本机单人使用的长篇小说写作辅助工具**（B/S 架构，浏览器访问）。

不是产品，不是 SaaS，不给第二个人用。所有设计决策以"作者本人写得更快、更稳、不崩"为唯一判据。

## 3. 核心命题：AI 该接管什么

**判据：AI 只接管"人做不到"的事，不接管"人不愿意做的苦力"。**

| 交给 AI（人做不到）                     | 留给作者（人是强项）     |
| ------------------------------- | -------------- |
| 跨几十章的**一致性**（人设不崩、设定不自相矛盾）      | 故事结构与大纲        |
| 跨几十章的**伏笔追踪**（埋了没、收了没、哪条烂尾）     | 文风与审美判断        |
| 长篇**上下文压缩**（写到第 80 章还记得前面发生了什么） | 情节创意与走向选择      |
| **设定校验**（写的内容是否违反已定规则）          | 是否采纳 AI 的每一个建议 |
| 写后**自动沉淀**（记忆/摘要/大事记/新实体）       | 最终成稿的所有文字      |

### ⚠️ 关于套路模板（2026-09-12 定型：结构资产库）

**上一版写"套路模板价值最低、列为删除对象"，这个判断是错的，已推翻。**

- **流水线小说（网文量产）恰恰最需要套路模板**——这是它的生产工具，不是可选项。
- 目前的 7 条写死模板（秘境夺宝/宗门大比/穿越重生…）之所以看起来没价值，
  **不是因为模板没用，而是因为它是硬编码的、题材绑定的、且不能编辑**——与上文"题材无关"原则直接冲突。
- **2026-09-12 定型**：模板 = **从真实网文逆向凝练的结构资产**，已按下方 §3.5 的四层模型落地（Phase 7）。

**修正后的判据**：不是"AI 别碰创意"，而是"**AI 提供结构与素材，作者掌握取舍**"。

### 3.5 结构资产库（Phase 7，2026-09-12 定型）

**愿景**：把真实网文逆向拆解为**可跨书复用的结构资产**，让"写新篇"变成"选套路 → 选角 → 出计划 → 逐章生成"。

**四层资产模型**（每层是上一层的抽象）：

```
① 章概括（匿名化代称世界：主角/友·配角1/敌·宗门2/境界1~N，无源书专名）
   → ② 情节段 beat（事件粒度，2~6 章）
   → ③ 故事弧 arc（一个完整套路 = 一个爽点周期，8~15 章）
   → ④ 情节模板 template（跨书抽象：结构 phase→beat→variants + 人格化角色槽位 cast）
        ↓ 计划生成（模板检索 + 向量选角 casting：槽位 ← 本书真实角色）
   → 篇计划 article_plan（作者拍板）→ 逐章生成（任务卡注入）
```

> ⚠️ 与四层**正交**的第五项资产：**角色状态台账**（Phase 7.3.5）—— 四层解决"**结构**从哪来"，
> 台账解决"**人**能不能用"。它是模板层与计划层之间的护栏，不参与抽象递进。见 03 §7.3.5。

**四大支柱机制**（讨论沉淀，缺一不可）：

| 支柱 | 解决什么 | 状态 |
|---|---|---|
| **匿名化归一** | 模板带源书专名 → 计划照抄源书（实测：云岚宗原名照搬） | ✅ 已落地（16 个源书专名命中 0） |
| **弧归并** | 段是事件粒度，模板需要完整套路粒度（粒度错位） | ✅ 已落地（84 段 → 28 弧） |
| **角色向量选角** | 跨模板聚合时角色混乱；选角不可解释 | 🔴 待实现（Phase 7.3） |
| **角色连续性**（2026-09-12 新增） | 死角色被复活、久缺席角色被硬召回、篇间角色莫名消失；**且选角本身必须以角色状态为前提** | 🔴 待实现（Phase 7.3 并入 A 档 / 7.3.5） |

**结构资产库的四条验收门槛**：
1. **检索门槛**：模糊口述能召回正确模板族（✅ 已通过：6 组口述 Top1 命中 6/6，30 模板规模）
2. **反抄袭门槛**：计划中不出现源书专名（✅ 匿名化后源书专名物理不存在；prompt 铁律双保险）
3. **选角门槛**（7.3 完成后验收）：同一配角在整篇计划中身份一致；选角有可解释的匹配分数
4. **不复活门槛**（7.3.5 完成后验收）：`已死` 角色不出现在计划中；久缺席角色被召回时**必须给出回归理由**；
   上一篇在场、本篇消失的角色**必须被显式交代**（三者均为代码层校验，不依赖模型自觉）

### 3.6 角色资产库（2026-09-15 立项 —— 与结构资产库**正交**的第二条资产线）

> 详细路线见 `03 §8 角色立体化专项`。此处只定义**目标与边界**。

**为什么单独立项**：结构资产库解决「**剧情结构**从哪来」，角色资产库解决「**人**能不能立起来」。
两者正交 —— 模板再多，角色是空卡（实测 `personality` 5/5 全空），生成出来的仍是「黑袍人」。

**借鉴层级模型（四层，方法论基石）**：

| 层 | 内容 | 借鉴 | 理由 |
|---|---|---|---|
| **L1 功能位** | 「主角起步期的引路人」 | ✅ | 跨书高度可复用 |
| **L2 性格 × 位阶** | 「自私的长老」/「自私的散修」 | ✅ | **单给性格有害**——性格脱离位阶无法判定行为（AI 会给「无恶不作的小混混」配「见义勇为」） |
| **L3 具体设定** | 残魂成因、退婚、专名 | ❌ **刻意不给** | 与本书世界观强耦合，一旦提供必被照抄 |
| **L4 行为逻辑** | 语言风格、思维方式、信念 | ⏳ 待建 | 需回源重抽（S5），前置条件硬性 |

**成功标准（角色侧，与 §4 主闭环并行）**：
1. **有名**：新角色必须有具体姓名（除「刻意隐藏身份」类，且要求有「代称→真名」归并路径，不许永久悬空）
2. **有魂**：`personality` 等主观字段**不为空**（当前 5/5 全空）
3. **有据**：关系在章节生成后自动落表（`relations` 当前 0 行），并在后续生成时一跳注入防设定遗忘
4. **不漂移**：角色可随剧情生长（主观项变更走待审批），可回档到任意历史版本
5. **不雷同**：同一功能位跨书检索需做**多样性**（排除最近用过 + 跨书组轮换）——库大≠多样，top-k 会稳定命中同一批

**明确不做**（防范围漂移）：
- ❌ 不做全库快照式回档（粒度太粗，改为单角色 revision）
- ❌ 不做「常驻角色配额配置表」（本质是用配置模拟剧情判断，属调参地狱；优先交给计划自身判断）
- ❌ 不把主观项（性格/信念）交给自动覆盖（一章的剧情表现会带偏人设）

## 4. 预期效果（成功标准）

一条主线闭环，跑通即算成功：

```
作者写/聊剧情 → AI 生成章节（流式，可中断）
              → 写后自动沉淀（记忆/摘要/大事记/新实体/伏笔）
              → 下一章自动带上前情、设定、伏笔
              → 作者随时查"埋了哪些伏笔没收""前面发生过什么"
```

**可验收的四条硬指标**：

1. **不崩**：写到第 50 章时，AI 仍准确知道前 49 章发生了什么（靠记忆层，不靠硬塞全文）
2. **不飘**：生成的正文不违反已录入的设定（靠设定校验，不是靠祈祷）
3. **不漏**：埋下的伏笔能被追踪到回收或标记为烂尾
4. **改得动**：改任何一处代码后，能在 5 分钟内确认没改坏（靠测试 + 日志 + 变更记录）

**结构资产库的四条验收门槛**（Phase 7，2026-09-12 增补，同日在 §3.5 补第四条）：

5. **不照抄**：由模板生成的篇计划中，不出现源书的人名/宗门/功法（✅ 匿名化归一已物理消除）
6. **不换人**：同一配角在整篇计划中身份一致（🔴 待 7.3 角色向量选角 + casting 锁定）
7. **召回准**：模糊口述能召回正确模板族（✅ 已通过：6 组口述 Top1 命中 6/6）
8. **不复活**（2026-09-12 增补）：已死角色不进计划；久缺席角色被召回必须带回归理由；篇间角色消失必须被交代
   （🔴 待 7.3.5 角色连续性 —— 详见 03 §7.3.5）

### 5.1 检索能力：已升级（2026-09-10 完成）

**原状**：目录 + 关键词（2-gram）+ 按需加载（`LOAD_REFS` / `LOAD_SETTING`），能用但受字面匹配限制。

**升级方向（下表各项已全部实施 —— Phase R A 线 A1~A6，2026-09-10 真机验收）**：

| 项      | 说明                                             |
| ------ | ---------------------------------------------- |
| Embedding | **硅基流动 BAAI/bge-m3**（免费档，2026-09-09 选定）    |
| 重排 Rerank | **硅基流动 BAAI/bge-reranker-v2-m3**（免费档，2026-09-09 选定） |
| 存储     | 计划迁移到**向量库**                                    |
| 高级检索   | 部分场景（人物关系 / 事件因果 / 势力博弈）**GraphRAG 更合适**       |
| 检索策略   | **Hybrid 混合检索**（向量 + 关键词 + 图谱）                  |

> **状态：已完成 ✅（2026-09-10）**。存储用 **sqlite-vec**（`vec_index` 虚拟表，带 `project_id`/`source_type`

> 详见 02 已实现清单、05 §6.5（实施记录已归档：`docs/_archive/Phase0-4与R-实施记录归档-2026-09-12.md`）。
