## 2. 🔴 铁律（违反即回退）

### 2.1 准确性铁律

1. **不许凭读代码或读旧文档下结论。** 判断模块是否可用，以 `02-已实现清单.md` 为准；未实测的一律标 🟡，不许标 ✅。
2. **更新 02 必须实测**：改完代码要真发请求验证，然后把结果回填 02（含验证方式与日期）。
3. **不许说"应该可以""大概没问题"**。不确定就标 ⚠️ 存疑并写清疑点。
4. 发现 02/04/05 与代码不符 → **先改文档再改代码**，并把更正记录进 `CHANGELOG.md`。

### 2.2 代码铁律

1. **流式生成器内严禁访问请求级 DB session / ORM 对象。** 必须自建 `gen_db = _db.SessionLocal()`（模块引用，非直接 import），`finally` 关闭。见 04-C1。违反会导致 `DetachedInstanceError` → 流中断。
2. **SSE 所有业务事件必须在 `event: done` 之前发完。** 见 04-C2。
3. **禁止用 `print` 调试**——一律 `logging`。禁止打印用户正文/请求体/对话历史（**Phase 1.1 已全量清理完毕**：2026-09-10 清理 5 处，含 gateway 写盘泄漏；改动后仍须守此律）。
4. **禁止把异常文案写入章节正文**（`chapter.py` 曾把 `[模型调用失败…]` 落库）。
5. **前端 `fetch` 必须校验 `resp.ok`**（`chapter.js` 曾漏，导致界面永久卡在"生成中"）。
6. **有 alias 的 Pydantic schema，`model_dump` 必须带 `by_alias=True`**。见 04-C4。

### 2.3 流程铁律

1. **一次只改一个模块。** 改完必须验证 + 更新 02/03 + 记 CHANGELOG，再动下一个。
2. **动业务代码前先确认 Phase 0 是否已完成**（测试骨架 + logging + CHANGELOG）。未完成则先补。
3. **改后端后必须提醒用户手动重启**（`E:\` 共享盘 uvicorn reload 不生效）。见 04-A1。
4. 沙箱内起后端一律 `DEV_RELOAD=0`（否则产生关不掉的 8000 孤儿进程）。见 04-A2。
5. Python 固定用 `E:\AI小说创作\.venv\Scripts\python.exe`，**不是** WorkBuddy 受管环境。
6. **阶段规划做完必须立即归档**；**没做完必须显式标出剩余项**（禁止把「计划」写成「修复」）；
   未完成项一律登记进 `docs/08-遗留问题总表`，不许散落在实施记录里。**完整规则见 07 §5.1。**

## 4. 常见误判（别再犯）

| ❌ 错误判断              | ✅ 正确                               |
| ------------------- | ---------------------------------- |
| "数据库 0 行 = 这模块是死的"  | 0 行可能是未使用/未触发/走默认值。必须 grep ORM 读写点 |
| "旧 README 标 ✅ 就是能用" | 旧 README 把桩模块标成 ✅，已被证伪多次。**只信 02** |
| "数据库里 8 章 = 写了 8 章" | 行数可能含已删作品留下的孤儿。先做 `project_id` 差集再引用任何行数（04-D6）。**2026-09-10 已清 102 行，但方法照旧**，且新表要记得登记进级联删除 |
| "短生成测试通过就没问题"       | 中后段退化必须长输出才复现（04-B1）               |
| "某功能价值低 → 可以删" | **先确认它服务哪种创作模式**。精品单本 vs 流水线量产，同一个功能价值可以完全相反（套路模板就是反例，见 01） |
| "两个模型同时坏了 = 模型问题"   | 先怀疑公共链路：超时/网关/后端未重启（04-B9）         |
| "约束加得越多 AI 越听话"     | 禁忌类必须互斥，叠加会逼出病态输出（04-B5）           |
| "建卡注入原型 = 改建卡 prompt" | **建卡根本没有 prompt**（`confirm_planned_char` 是纯写库，拿作者手填 attrs）。`_plan_prompt` 属规划阶段，彼时 `new_chars` 只有名字、无人格信息。**改前先读码确认真实注入点**（03 §8.1） |
| "性格标签可以单独借鉴"       | 性格脱离位阶会导致**错误匹配**（AI 给「无恶不作的小混混」配「见义勇为」）。必须「性格 × 位阶」组合（03 §8.2） |
| "库里模板够多就不会雷同"      | top-k 语义近邻**命中集稳定**，库大只会「稳定地雷同」。解法在检索层（排除最近用过 + 跨书组轮换），不在库容（03 §8.3） |
| "禁止代称越严格越好"       | 神秘感代称是叙事刚需（钩子）。正解是**分流**：普通配角必须有名；隐藏身份允许代称但要求「代称→真名」归并路径（03 §8.6） |
| "角色数量少就加配额配置表"     | 配额表本质是**用配置模拟剧情判断**（战场篇/冷淡篇只有模型读剧情才知道）→ 调参地狱。改用「舞台切换显式化 + 人口基线提示」（03 §8.6） |
