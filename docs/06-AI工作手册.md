## 2. 🔴 铁律（违反即回退）

### 2.1 准确性铁律

1. **不许凭读代码或读旧文档下结论。** 判断模块是否可用，以 `02-已实现清单.md` 为准；未实测的一律标 🟡，不许标 ✅。
2. **更新 02 必须实测**：改完代码要真发请求验证，然后把结果回填 02（含验证方式与日期）。
3. **不许说"应该可以""大概没问题"**。不确定就标 ⚠️ 存疑并写清疑点。
4. 发现 02/04/05 与代码不符 → **先改文档再改代码**，并把更正记录进 `CHANGELOG.md`。
5. **用户陈述与文档冲突时，先核查现场证据再信文档**（历届交接验证：用户的方向性纠偏多次正确）。

### 2.2 代码铁律

1. **流式生成器内严禁访问请求级 DB session / ORM 对象。** 必须自建 `gen_db = _db.SessionLocal()`（模块引用，非直接 import），`finally` 关闭。见 04-C1。违反会导致 `DetachedInstanceError` → 流中断。
2. **SSE 所有业务事件必须在 `event: done` 之前发完。** 见 04-C2。
3. **禁止用 `print` 调试**——一律 `logging`。禁止打印用户正文/请求体/对话历史。
4. **禁止把异常文案写入章节正文**（04-C10：占位文案只进 error_notes，走 `_can_persist` 闸）。
5. **前端 `fetch` 必须校验 `resp.ok`**（04-C13）。
6. **有 alias 的 Pydantic schema，`model_dump` 必须带 `by_alias=True`**（04-C4）。

### 2.3 流程铁律

1. **一次只改一个模块。** 改完必须验证 + 同步下游 + 记 CHANGELOG，再动下一个。
2. **Python 固定用 `.venv\Scripts\python.exe`**（04-A4/A15：全局 Python 缺 sqlite_vec 会假红）；跑单测设 `NA_LOG_DIR` 临时目录（04-F7）。
3. **改后端后必须提醒用户手动重启**（04-A1）；沙箱起后端一律 `DEV_RELOAD=0`（04-A2）。
4. **阶段规划做完必须立即归档；没做完必须显式标出剩余项**（禁止把「计划」写成「修复」）；未完成项一律登记进 `docs/03 路线图`（就地改行）。
5. **动生产库前先备份**（DB 级 Copy-Item + 行级备份禁 `default=str`，见 04-F5）；**入库/重嵌前探活 9377 网关、跑完 verify 向量块>0**（04-F1）。
6. **新想法记 flow to_plan 节点，三天冷静期；活跃任务 WIP 上限 1 主线+1 支线。**

## 3. 改这几类东西前的强制检查

| 你要改… | 先读 | 重点 |
|---|---|---|
| **提示词 / 系统提示 / SKILL** | 04-B5、B6 | 约束叠加会反向致病态输出；负面措辞会 priming |
| **解码参数（温度/惩罚/max_tokens）** | 04-B1、B8、B10、B13 | Qwen3.x+ModelScope 必须禁重复惩罚（按系匹配不按版本字面量）；推理模型 max_tokens 是思考+正文共享预算 |
| **模型适配器 / 新增厂商** | 04-B2、B3、B7 | 思考字段厂商白名单；新模型先跑最小探测脚本看原始 SSE 帧 |
| **流式 / SSE 相关** | 04-C1、C2、C10、E10 | DetachedInstanceError + 事件时序 + 思考阶段保活 |
| **前端弹窗（有流程状态的）** | 04-C6 | `el-dialog` 常驻挂载不销毁状态，必须 watch 复位 |
| **数据库表结构** | 04-A5、F2、F5 | SQLite 无迁移工具只能加列；JSON 列 deepcopy；备份禁 default=str |
| **切原子 / 模板入库** | 04-A17、E23、F1 | 唯一键假设必须 assert；入库前探活网关 |

## 4. 常见误判（别再犯）

| ❌ 错误判断 | ✅ 正确 |
|---|---|
| "数据库 0 行 = 这模块是死的" | 0 行可能是未使用/未触发/走默认值。必须 grep ORM 读写点（04-D3） |
| "旧文档标 ✅ 就是能用" | **只信 02**（04-D2：文档会骗人，代码也会） |
| "数据库里 8 章 = 写了 8 章" | 先做 `project_id` 差集再引用行数（04-D6），注意 `__global__` 豁免（04-C12） |
| "短生成测试通过就没问题" | 中后段退化必须长输出才复现（04-B1/D1） |
| "两个模型同时坏了 = 模型问题" | 先怀疑公共链路：超时/网关/后端未重启（04-B9，犯过 2 次） |
| "约束加得越多 AI 越听话" | 禁忌类必须互斥，叠加会逼出病态输出（04-B5） |
| "禁止代称越严格越好" | 神秘感代称是叙事刚需，正解是分流（03 §8.6） |
| "按对账数字凑上了就下结论" | 数字必须带维度标签（scale/status），join 出全部维度再 group（04-E24） |

## 5. 收工四件套（唯一收尾纪律，合并了原 06/agent-flow/HANDOFF 三套）

1. **flow 图同步**：update_node 改状态 → `agent-flow status` 复核落盘（不落盘就直接编辑 flow.json）→ `validate_graph` → `render_html`

4. **git 提交**（多行信息用 `git commit -F <文件>`，04-F4）→ push 前探活远端（04-A7b）
