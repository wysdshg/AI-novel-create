# 02 · 能力清单（按模块 · 实测版）

> **本文只回答一个问题：项目现在有什么能力、能不能用、凭什么信。**
> 不记"怎么做的、做到一半的"——规划与待办看 `03`，实施流水看 `_archive/`，踩坑看 `04`。
>
> 🔴 三条纪律：
> 1. 每个状态必须带**验证方式 + 日期**（三要素），不许凭"读代码 / 文档说了"标 ✅；
> 2. 判断模块死活必须 **grep ORM 读写点**，不能看数据库行数（0 行 ≠ 死，有行 ≠ 活）；
> 3. **信任顺序：数据库实况 > 代码 > 本文档**——文档是地图，地图旧了重画，别怀疑地形。
>
> 状态标记：✅ 实测通过（写清怎么验的）｜🟡 代码/构建确认（未端到端）｜⏸ 冻结（判据触发才做）
>
> 最后核账：**2026-10-01**（pytest **547 全绿** + API 路由 **121 条** + 数据库 **57 张表**逐项实数 + 分域走查）
